数据库管理系统 DBMS 用于定义、创建、维护和使用数据库。关系模型以二维表组织数据，行表示记录，列表示属性，表之间通过外键建立联系。

SQL 是关系数据库的标准查询语言，分为数据定义 DDL（CREATE/ALTER/DROP）、数据操作 DML（INSERT/UPDATE/DELETE）、数据查询 DQL（SELECT）和数据控制 DCL（GRANT/REVOKE）。SELECT 语句的执行顺序是 FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT。

JOIN 用于多表查询：内连接 INNER JOIN 只返回两表都匹配的记录；左连接 LEFT JOIN 保留左表全部记录，右表无匹配时填空 NULL；右连接 RIGHT JOIN 保留右表全部记录；全外连接 FULL OUTER JOIN 保留两表全部记录。左连接与内连接的区别在于：内连接会丢弃未匹配的左表行，左连接会保留这些行并用 NULL 填充右表字段。MySQL 原生不支持 FULL OUTER JOIN，可用 UNION 模拟。

数据库范式用于减少冗余和更新异常。第一范式 1NF 要求属性原子不可再分；第二范式 2NF 消除非主属性对主键的部分依赖；第三范式 3NF 消除传递依赖；BCNF 进一步消除主属性对码的部分和传递依赖。

索引是提升查询性能的数据结构，MySQL InnoDB 使用 B+ 树索引。聚簇索引的叶子节点存储整行数据，非聚簇索引叶子节点存储主键值，回表指通过二级索引找到主键后再查聚簇索引。索引不是越多越好，会降低写入速度并占用空间。

事务具备 ACID 特性：原子性 Atomicity 保证操作全部成功或全部回滚；一致性 Consistency 保证数据从一个合法状态转到另一个合法状态；隔离性 Isolation 保证并发事务互不干扰；持久性 Durability 保证提交后数据永久保存。

并发事务可能引发脏读、不可重复读和幻读。MySQL InnoDB 的默认隔离级别是 REPEATABLE READ，通过 MVCC 多版本并发控制和 Next-Key Lock 解决大部分幻读问题。

数据库设计步骤包括需求分析、概念设计（E-R 图）、逻辑设计（关系模式）和物理设计。E-R 图包含实体、属性和联系，联系分为一对一、一对多和多对多，多对多联系需转换为中间表。

数据库原理及应用课程的课程项目通常要求完成一个完整业务系统的建表、索引设计、SQL 查询和简单性能优化报告。
